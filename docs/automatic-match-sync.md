# Автоматическое обновление матчей

Workflow `Automatic match results` запрашивает шесть турниров football-data.org
(PL, PD, BL1, SA, FL1, CL) на 7, 22, 37 и 52 минуте каждого часа.
GitHub может задержать или пропустить запуск; бесплатный источник отдаёт результаты
с задержкой. Это не гарантия LIVE или обновления ровно раз в 15 минут.

Каждый запуск обрабатывает интервал UTC от двух дней назад до семи дней вперёд.
Старые незавершённые матчи требуют ручного импорта через админку.
Между турнирами выдерживается 10 секунд. При HTTP 429 запуск прекращается.
Составы и эмблемы автоматически не импортируются.

## Безопасность

Endpoint `/api/sync-results` принимает только POST в Vercel Production.
Подпись RS256 проверяется по фиксированному JWKS GitHub; обязательны точные
repository/owner IDs, main, имя workflow, audience, короткий срок токена и
событие schedule/workflow_dispatch. Токены и ключи не записываются в журнал.
GitHub не хранит ключи поставщика или Supabase.

Service-only RPC `claim_automatic_match_sync` использует блокировку транзакции,
уникальную пару турнир/run_id и десятиминутный интервал между запусками.
Повтор того же run_id не импортирует данные заново: для ручного повтора создайте
новый workflow_dispatch после завершения интервала.

## Проверка и обслуживание

1. GitHub → Actions → Automatic match results → Run workflow → main.
2. Проверьте результаты всех шести турниров в логе задания.
3. FOOTBAZED → Админка → Обзор: голубой индикатор появляется только после
   успешной проверки всех шести турниров не более 45 минут назад.
4. Админка → Журнал: запуск, успех и ошибка сохраняются отдельно для каждой лиги.
   Ноль обработанных матчей допустим: на выбранные даты может не быть игр.
5. При длительной задержке проверьте Actions. GitHub может отключить scheduled
   workflow публичного репозитория после 60 дней без активности.

Остановка: Actions → Automatic match results → меню ⋯ → Disable workflow.
Для отката сначала остановите workflow, затем откатите код через обычный PR.
Аддитивные индексы и неиспользуемый service-only RPC можно оставить:
они не меняют существующие пользовательские данные.

Перед выпуском нужны миграция, pgTAP, полный CI, подтверждение production SHA
и успешный реальный запуск. Наличие файла расписания само по себе не означает,
что автоматическая синхронизация уже работает.
